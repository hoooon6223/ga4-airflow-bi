# 지표 정의서

작성일: 2026-11-25
이 문서는 대시보드와 마트에 쓰는 모든 지표의 유일한 기준이다. 구현할 때는 각 정의를 dbt 모델 `description`에 같은 문장으로 옮기고, metric_id로 추적한다.
설계 배경과 근거 숫자는 [`01_design.md`](01_design.md)에 있다.

## 공통 규칙

| 항목 | 정의 |
|---|---|
| 운영 기간 | 2020-11-30 ~ 2021-01-24 (56일). 결함 구간(`data_incidents`)은 KPI와 비교 기준에서 제외 |
| 날짜 | `event_date` (GA4 속성 시간대 기준) |
| 통화 | USD |
| 세션 키 | `user_pseudo_id` + `ga_session_id` |
| 세션의 날짜 | 이벤트가 있었던 날짜마다 1번씩 센다 (자정을 넘긴 세션은 양쪽 날짜에 각각 1번) |
| 주문 | 거래번호(`transaction_id`) 1개 = 주문 1건. `''`, `(not set)`은 주문이 아님 |
| 주문의 대표 이벤트 | 같은 거래번호 중 처음 찍힌 이벤트 |
| 주문의 세션 | 거래번호가 처음 나타난 세션 |
| 빈 구매 | `purchase` 이벤트 중 거래번호가 `''`/`(not set)`이고 `purchase_revenue`가 null인 것 |
| 거래번호 없는 구매 | `purchase` 이벤트 중 거래번호가 `''`/`(not set)`인 것 (매출 유무 무관). 빈 구매를 포함한다. 운영 기간에는 둘이 같다 |
| 구매 세션 | `purchase` 이벤트가 1개 이상 있는 세션 (정상이든 아니든) |
| 세션 수의 기준 | 마트·대시보드는 세션 × 날짜. "기간 내 서로 다른 세션" 기준 숫자는 설계 문서에 따로 표시 |
| 날짜를 넘는 중복 거래번호 | 이전 날짜의 `f_orders`에 이미 있는 거래번호는 주문으로 세지 않는다 |
| 정상 주문 세션 | 주문(거래번호 있는 구매)이 1건 이상 있는 세션 |
| 비교 기준 | 지난주 같은 요일, 최근 7일 평균. 결함 구간과 차단일은 제외한다. 지난주 같은 요일이 제외된 날이면 "비교 불가"로 두고, 7일 평균은 유효한 날이 5일 이상일 때만 계산한다 |

## KPI

| metric_id | 지표 | 분자 | 분모 | 비고 |
|---|---|---|---|---|
| K01 | 매출 | 주문별 `purchase_revenue` 합 | — | 값을 그대로 쓴다(이 데이터에서는 세금이 포함돼 있지 않음. 배송비는 수집되지 않음). 환불 미반영(총매출). 빈 구매 때문에 약 4~5% 과소 집계. 운영 기간 $221,762 |
| K02 | 주문 수 | 주문 건수 | — | 빈 구매 제외. 약 4~5% 과소 집계 |
| K03 | 세션 수 | 세션 키 × 날짜의 개수 | — | 빈 구매 세션 포함 |
| K04 | 주문 전환율 | 주문 수 (K02) | 세션 수 (K03) | Universal Analytics의 전자상거래 전환율과 같은 정의 |
| K05 | 객단가 | 매출 (K01) | 주문 수 (K02) | |

**항등식**: K01 = K03 × K04 × K05 (DQ6에서 매일 확인)

## 쪼개 보는 기준

| 기준 | 값 | 정의 |
|---|---|---|
| 기기 | 데스크톱 / 모바일 | `device.category`. tablet은 모바일에 포함 |
| 신규/재방문 | 신규 / 재방문 | 신규 = `ga_session_number` = 1, 그 외 재방문. 재방문 = 30분 이상 쉬었다가 같은 브라우저로 다시 온 방문. 재구매와 다름 |

K01~K05, F01~F13, S01은 전체 / 기기별 / 신규·재방문별로 계산한다.
주간 값의 세션 수는 일별 합계가 아니라 그 주의 서로 다른 세션 수로 센다.

## 데이터 품질 지표

| metric_id | 지표 | 분자 | 분모 | 판정 | 기준 |
|---|---|---|---|---|---|
| DQ1 | 데이터 도착 / 이벤트 총량 | 그날 raw 이벤트 수 | 직전 7일 기준선 평균 | 차단 | 0건(미도착)이면 즉시 차단. 기준선이 있으면 비율 < 0.3이면 차단 |
| DQ2 | 거래번호 없는 구매 세션 비율 | 거래번호 없는 구매가 1개 이상 있는 구매 세션 수 | 구매 세션 수 | 경고 / 차단 | 경고: ≥ 20% 그리고 해당 세션 ≥ 5. 차단: ≥ 40% 그리고 해당 세션 ≥ 5 |
| DQ3 | 이벤트별 수집량 급감 (조회·장바구니·결제·구매 각각) | 그날 이벤트별 세션 수 | 직전 7일 기준선 평균 | 경고 | 비율 < 0.1 (기준선 평균이 20세션 이상일 때만) |
| DQ4 | 주문 매출 대사 | \|Σ `purchase_revenue` − Σ `item_revenue`\| | Σ `purchase_revenue` | 경고 | > 2% |
| DQ5 | 다중 주문 세션 비율 | 주문이 2건 이상인 세션 수 | 주문이 있는 세션 수 | 경고 | ≥ 25% 그리고 다중 주문 세션 ≥ 5 |
| DQ6 | 집계 대사 | 기기별 합 = 전체, 신규+재방문 = 전체, K01 = K03 × K04 × K05, KPI = f_orders | — | 차단 | 불일치 시 차단 (dbt 테스트 `dq6_*`) |

**기준선**: 직전 7일 중 결함 구간·이전 차단일이 아닌 날의 평균. 유효일이 5일 미만이면 DQ1(미도착 제외)과 DQ3은 `insufficient_baseline`(기준 부족)으로 두고 판정하지 않는다. 운영 기간에는 11/30~12/4가 해당한다.

**DQ 진단 정보** (판정에는 쓰지 않음): DQ2 해당 세션의 사용자 수·세션 수·이벤트 수, 기기별 분포, 브라우저 목록

모든 값은 **초기값**이다. 운영하면서 조정한다. 평소 범위는 운영 기간 중 기준선이 있는 51일(12/5~1/24) 기준이다.

| 체크 | 평소 범위 | 알려진 사고 | 기준을 둔 이유 |
|---|---|---|---|
| DQ1 | 최저 0.51 (12/20), 연휴 0.54~0.61 | 반쯤만 도착한 사례 없음 | 연말에 실제로 방문이 절반까지 줄어서, 그보다 훨씬 낮은 0.3에 둠 |

**1/26 사고 재현 결과** (`ga4_mart_test`): DQ2 = 60.8%(51세션 중 31) → 차단, `gate_block` 실패(종료 코드 1). 진단 정보는 사용자 31명·세션 31개, 데스크톱 15·모바일 16, 여러 브라우저 → 사이트 전체 문제로 판단. DQ1·DQ3·DQ4·DQ5는 정상 → 이 사고는 DQ2만 잡는다.

## 알려진 한계

- 주문·매출은 빈 구매 때문에 실제보다 약 4~5% 과소 집계된다 (운영 기간에 빈 구매만 있는 세션 140개 / 구매 세션 3,047개).
- 사용자 식별이 브라우저 기준이라, 신규는 실제보다 많게, 재방문은 실제보다 적게 잡힌다.
- 환불 데이터가 없어 총매출만 계산한다.
- 현업이라면 매출·주문은 주문 DB가 기준이다. 이 데이터에는 주문 DB가 없어서 GA4로 대신한다.
